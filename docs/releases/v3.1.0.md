# ATC 3.1.0

- **Typed Bazel graph inspection:** `bazel.query` and `bazel.cquery` run through `atc exec`, MCP, and `atc batch` under the workspace lock and build slot. The query expression is one literal argument. Output is an allowlisted format written to a relative `outputFile`, published only when Bazel exits 0 inside `maxOutputBytes`, with byte count and SHA-256. A limit breach, failure, or interrupted write leaves no artifact. (#26)
- **Custom Gradle and Bazel executables (`--executable`):** `gradle.tasks` and all `bazel.*` operations (`build`, `test`, `coverage`, `run`, `query`, `cquery`, `series`, `clean`) now accept an explicit `executable` path or command name — including polyglot wrappers without `#!` shebangs on macOS/Linux such as `intellij-community`'s `./bazel.cmd`. (#15, #16)
- **Force-like accountability on custom executables:** Specifying `executable` acts as an override in and by itself (no `--force` required), carrying the same responsibility notice, `overridden` reporting, `state.forcedRuns` / `atc-audit.jsonl` audit entry, and workspace failure attribution as `--force`. (#16)
- **Separated leading-dash passthrough arguments:** `atc exec bazel run` (`--run-arg`) and `atc exec ios launch` (`--launch-arg`) now accept separated leading-dash values (`--run-arg --verbose`, `--launch-arg --uitesting`) in addition to inline `--run-arg=--verbose`. (#12, #17)
- **Windows lock and heartbeat hardening:** Removed hardware `fsync` barriers on ephemeral lock files (`owner.json`, `breaker.*.json`), added break-claim release retries in `releaseLock`, and raised the background boot-heartbeat worker lock timeout to eliminate transient lock timeouts on Windows VMs. (#12, #17)
