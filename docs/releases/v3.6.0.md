# ATC 3.6.0

- **Bazel 9 builds work again (#32):** ATC no longer adds `--local_ram_resources`, which Bazel 9 removed, so coordinated Bazel 7, 8, and 9 builds all run. ATC adds only caps that every version accepts: Bazel `--jobs`, Gradle `-Dorg.gradle.workers.max`, and `xcodebuild -jobs`. RAM is still admitted by ATC before the build starts, but Bazel no longer gets its own RAM limit.
- **Caps cannot be loosened:** ATC finds the Bazel subcommand even after startup options, and places `--jobs` after `--config` and caller flags. A `.bazelrc` file, a config, or a flag cannot override it. The Gradle worker cap now comes first in argv.
- **`flags` on Gradle and Bazel build ops:** pass tool options the catalog does not model, one token each (`--name`, `--name=value`, or Gradle `-Dkey=value`). The tool rejects flags it does not know, so ATC keeps no per-version flag lists. ATC refuses only flags it owns, even with `--force`: resource caps, Gradle daemon lifecycle and `org.gradle.daemon.*`, `--continuous`, `jvmargs`, and anything that moves the build root or Gradle user home. Using `flags` counts as a forced run, like `executable`. A Gradle request with `flags` is admitted as a cold build, and ATC reports this as a notice.
- **Exclusions:** Gradle `excludeTasks` passes `--exclude-task`, and Bazel `excludeTargets` passes negative patterns after `--`.

**Full changelog:** https://github.com/rock3r/atc/compare/v3.5.0...v3.6.0
